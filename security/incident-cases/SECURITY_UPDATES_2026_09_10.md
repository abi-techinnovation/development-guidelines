# 2026年9〜10月のセキュリティインシデントと脆弱性情報

確認日: 2026年10月26日
対象期間: 原則2026年9月1日〜10月26日に公表・更新された情報

公開サーバー、業務システム、委託先のアクセス管理に関わる情報を取り上げる。全件を網羅した一覧ではない。以下の修正済みバージョンは確認日時点の情報であり、適用時には製品・OS提供元の最新告知を確認する。

## 国内組織への不正アクセス

JPCERT/CCは10月8日に注意喚起を公開し、10月23日に更新した。9月前後から国内組織で情報漏えいが相次ぎ、管理用APIへの不正な操作や、Webシェルの設置などを報告している。一般公開を想定していないBIツールや従業員向けシステムも被害を受けている。

技術情報は限定的で、すべての事案が同じ攻撃手法によるものではない。特定のCVEを修正すれば一連の被害を防げると判断しない。

運用では管理用APIと管理画面の公開範囲、サーバー側の認証・認可、環境設定ファイルやバックアップの露出を点検する。掲載されたIPアドレスは過去の調査の手がかりとして扱う。正規利用に戻っている可能性があり、IPアドレスの一致だけで侵害を断定しない。

出典: [JPCERT/CC 注意喚起](https://www.jpcert.or.jp/at/2026/at260030.html)

## NECの委託先への不正アクセス

NECは10月20日、開発・保守業務の委託先が9月下旬にサイバー攻撃を受け、窃取された正規アカウントの認証情報が悪用されたと公表した。顧客環境ではファイルの暗号化によるシステム停止が起き、関係者間で共有していたクラウドストレージのファイル漏えいも確認された。

公表文は特定のCVEを原因として示していない。脆弱性対応に加え、委託先端末からの接続、保守アカウントの権限、共有ストレージの閲覧範囲を見直す事例として参照する。これは公表された事実を踏まえた本資料の運用上の提案であり、NECが公表していない原因や対策の実施状況を示すものではない。

出典: [NEC 2026年10月20日公表](https://jpn.nec.com/news/info/20261020.html)

## PHPのリモートコード実行の脆弱性

The PHP Groupは10月21日、CVE-2026-109618、CVE-2026-109619を修正した。認証されていない攻撃者がリモートでコードを実行する可能性がある。Webリクエストを処理するPHPが対象となり、PHP-FPMだけでなくApacheのmod_phpなども含まれる。

修正済みバージョンはPHP 8.5.12、8.4.27、8.3.36、8.2.35。ディストリビューションや製品に組み込まれたPHPは、提供元の修正パッケージ情報も確認する。緩和策は特定の攻撃経路を減らすもので、更新の代わりにはならない。

10月23日にはセッションのシリアライズ方式を実行時に切り替える特殊な構成に関する追加告知も出ている。該当条件を公式告知で確認し、推奨される `session.upload_progress.enabled=0` の設定を検討する。すでに適用済みなら維持する。10月21日の修正バージョンへの更新だけで、追加告知の確認を省略しない。

JPCERT/CCはHTTPやPHPプロセスの異常などの調査を案内している。ただし、痕跡が見つからなくても未侵害とは断定できない。今回確認した告知を、実際の悪用確認や被害件数の根拠にはしない。

出典

- [The PHP Group 10月21日セキュリティ告知](https://www.php.net/archive/2026.php#2026-10-21-5)
- [The PHP Group 10月23日追加告知](https://www.php.net/archive/2026.php#2026-10-23-1)
- [JPCERT/CC PHP注意喚起](https://www.jpcert.or.jp/at/2026/at260033.html)

## SiteGuard Server Editionの脆弱性

EGセキュアソリューションズは10月14日、CVE-2026-106931を公表し、すでに悪用を確認したと説明した。統計機能が有効な場合に影響し、サーバー上でrootまたはSYSTEM権限で任意のOSコマンドを実行される可能性がある。統計機能は初期状態で有効になっている。

対象はVer2.20以降のうち、Apache版・Nginx版・IIS版ではVer8.00 Update5より前、FreeBSDのApache版・Nginx版ではVer7.00 Update6より前。IIS版のVer3.10〜Ver4.00 Update4は対象外となる。

更新またはパッチの適用で攻撃の痕跡が消える可能性があるため、適用前に管理画面から「診断情報」を取得して保管する。そのうえで修正済みバージョンまたは提供元のパッチを適用する。JPCERT/CCは回避策として統計機能の無効化も案内している。

出典

- [EGセキュアソリューションズ 公式告知](https://www.eg-secure.co.jp/siteguard/news/alert-202610-1)
- [JPCERT/CC SiteGuard注意喚起](https://www.jpcert.or.jp/at/2026/at260032.html)

## NetScaler ADCとNetScaler Gatewayの脆弱性

JPCERT/CCは9月28日に注意喚起を公開し、10月2日に侵害調査の情報を追加した。CVE-2026-88771とCVE-2026-88772は悪用が確認されている。前者は影響バージョンのすべての構成、後者はDTLSが有効な構成に影響する。GatewayのVPN仮想サーバーではDTLSが初期状態で有効となる。

通常版の修正済みバージョンは14.1-73.37と13.1-64.23。FIPS版は14.1-73.37 FIPS、13.1のFIPS・NDcPP版は13.1-37.279が基準となる。製品系列と構成を照合し、提供元が案内する修正を適用する。JPCERT/CCの告知では、この2件の回避策は提供されていない。

更新に加え、Webサーバーの設定変更、不審なファイルやプロセスなど、侵害後の痕跡も調べる。国内で観測された攻撃試行が、この脆弱性を狙ったものかは明らかになっていない。

出典: [JPCERT/CC NetScaler注意喚起と原典へのリンク](https://www.jpcert.or.jp/at/2026/at260029.html)

## 運用への反映

次の確認は、本資料が既存の運用方針に沿って提案するものである。

1. 外部公開資産について、製品名、バージョン、機能設定、管理者を照合する。WAFやVPN機器、組み込みランタイムも含める。
2. 悪用が確認されている製品や外部公開環境を優先して影響を判定する。対策まで時間がかかる場合は、製品の条件に応じて公開停止や接続元制限を検討する。これらを修正の代替とは扱わない。
3. 提供元が案内する証拠保全を先に行い、修正後も侵害の有無を確認する。未侵害の判定を、単一のIPアドレスや検知ルールに依存させない。
4. 認証情報の窃取が疑われる場合は、既存のインシデント対応手順に従い、証拠保全、隔離、認証情報の無効化・更新を進める。

基本方針は[公開サーバーセキュリティガイドライン](../PUBLIC_SERVER_SECURITY_GUIDELINE.md)、初動は[セキュリティマニュアル](../SECURITY_MANUAL.md#12-インシデント対応)を参照する。
